# NAS 的 IPv6 端口放行机制

> 目标：只让内网**一台设备**（NAS）从公网访问 `tcp/udp 36353-36354`，
> 并且在 ISP 更换前缀、设备重启、事件丢失等各种情况下**自动保持正确**。
>
> 相关脚本：`files/usr/sbin/nas-v6-firewall`、
> `files/etc/hotplug.d/iface/90-nas-v6`、
> `files/etc/init.d/ax6000-nas-v6-watch`。

## 1. 为什么需要这套机制

三个约束叠在一起，导致"在 LuCI 里点一下端口转发"解决不了：

1. **只有 IPv6 公网，没有 IPv4 公网**。WAN 侧是 RFC1918 + CGNAT（`10.27.x.x`），
   端口映射无从谈起，只能走 v6 直连。
2. **规则不能对全网段开放**。最初那条规则是 `dest='*'`，等于内网每台设备都开了这两个端口。
   要收窄到一台，就必须指定目的地址。
3. **地址是动态的**。前缀由 ISP 通过 DHPCv6-PD 下发，重拨、续租、局端调整都会让它变；
   写死地址过几天就失效，而且失效是静默的——外网访问不了，本地毫无感知。

## 2. 原理

### 2.1 关键事实：EUI-64

NAS 的 IPv6 用 EUI-64 接口标识，后 64 位由 MAC 确定性地推导出来：

```
MAC   e4:3a:6e:86:47:6e
      ↓ 第一字节翻转 U/L 位（e4 → e6），中间插入 ff:fe
IID   e63a:6eff:fe86:476e
```

所以一台设备的地址可以拆成两半：

```
240e:341:9b00:9e00 : e63a:6eff:fe86:476e
└──── 前缀 ────────┘ └─── 由 MAC 决定，永不变 ───┘
   会变（PD 下发）
```

**结论：变的只有前缀，设备身份（后缀）是常量。** 于是不需要"记住地址"，
只需要每次问一句"这台设备现在的全局地址是什么"。

### 2.2 解析链

```
① 内网 IPv4（默认 192.168.6.4，可用 ax6000.nas.ip 覆盖）
        │  ip neigh show dev br-lan  →  取 lladdr
        ▼
② NAS 的 MAC
        │  ip -6 neigh show dev br-lan  →  按 MAC 匹配
        ▼
③ NAS 当前的全局 IPv6
        │  uci set firewall.nas_v6_ports.dest_ip + fw4 reload
        ▼
   防火墙规则指向新地址
```

第 ① 步查不到时先 `ping` 一次该 IPv4 把邻居表填上；
第 ② 步没有任何候选时，走 2.4 的兜底。

### 2.3 三道校验（这是整套机制的核心）

邻居表是**缓存**，不能直接信。实测同一台 NAS 同时存在 4 条记录：

```
240e:...:9b00:9e00:e63a:6eff:fe86:476e  STALE   ← 当前前缀，可用
240e:...:9b4d:c300:e63a:6eff:fe86:476e  STALE   ← 上一轮 PD 的前缀，已废弃
fd31:...（ULA）                          fe80::...（链路本地）
```

旧前缀的条目不会因为前缀作废就消失，排序也不保证。所以候选地址必须同时满足：

| 校验 | 做法 | 挡掉什么 |
|---|---|---|
| **前缀校验** | 候选的 /64 必须属于 `br-lan` **当前持有**的公网前缀（跳过 ULA `fc00::/7`） | 旧前缀的残留地址 |
| **连通校验** | `ping6 -c 1 -W 1` 必须真有回应 | 已经不可达的地址 |
| **沿用当前值** | 规则里现有的 `dest_ip` 若仍通过上面两条，直接退出 | 多前缀/排序变化导致的来回改写 |

比较地址时**必须先归一化**：`::` 压缩写法会让朴素的 `cut -d: -f1-4` 取错段
（详见 §5 漏洞 ④）。脚本里的 `norm6()` 把任意写法展开成 32 位十六进制再比。

### 2.4 EUI-64 兜底

两道校验都不通过时（邻居表为空、全是旧前缀、设备刚上电还没完成 SLAAC），
脚本用「当前前缀 + 由 MAC 推导的后缀」直接算出地址，再用 `ping` 验证：

```sh
for p in $PREFIXES; do
    cand="$p:$(eui64_suffix "$NAS_MAC")"
    ping_ok "$cand" && { ADDR="$cand"; break; }
done
```

这一步不依赖任何缓存，是最后的保险。

### 2.5 触发：事件优先，定时兜底

| 触发源 | 时机 | 覆盖什么 |
|---|---|---|
| `hotplug.d/iface/90-nas-v6` | `wan` / `wan_6` 的 `ifup`、`ifupdate` | 前缀变化的主路径（PD 续租/重拨必然产生这两个事件） |
| `init.d/ax6000-nas-v6-watch` | 每 600 秒 | 事件丢失、事件早于 NAS 完成 SLAAC、极端的局端静默变更 |

定时器单次开销约 0.3 秒，**地址没变时不做任何写操作**。

### 2.6 幂等与并发

- **幂等**：解析结果与规则现有值（归一化后）相同 → 直接退出，不 commit、不 reload。
- **并发**：`flock -n /tmp/.nas-v6-firewall.lock`，hotplug 与定时器撞车时只有一个执行。
- **失败即不动**：任何一环拿不到结果，都只写一条日志并 `exit 0`，**绝不把规则改成
  "对所有人开放"**。最坏情况是规则指向旧地址（外网连不上），不会变成安全漏洞。

## 3. 脚本放在哪儿

### 3.1 仓库内路径（构建时注入 rootfs）

| 仓库路径 | 镜像内路径 | 作用 |
|---|---|---|
| `files/usr/sbin/nas-v6-firewall` | `/usr/sbin/nas-v6-firewall` | 一次性的「解析 + 写回」，核心逻辑 |
| `files/etc/hotplug.d/iface/90-nas-v6` | `/etc/hotplug.d/iface/90-nas-v6` | 接口事件触发，调用上面那个 |
| `files/etc/init.d/ax6000-nas-v6-watch` | `/etc/init.d/ax6000-nas-v6-watch` | procd 服务，每 10 分钟兜底 |

三个文件都以 `100755` 提交，`cp -a files/. ` 注入时保留权限。

### 3.2 不在仓库里的东西

| 位置 | 内容 | 为什么不在仓库 |
|---|---|---|
| `/etc/config/firewall` 的 `nas_v6_ports` 段 | 放行规则本身（`src=wan`、`family=ipv6`、`dest_port=36353-36354`、`dest_ip`） | 属于设备配置，且 `dest_ip` 会被脚本持续改写 |
| `/etc/config/ax6000` | 可选：`nas.ip`（默认 `192.168.6.4`）、`nas.mac` | 设备标识不放进公开仓库 |

### 3.3 持久化矩阵

| 操作 | 三个脚本 | `nas_v6_ports` 规则 | `ax6000.nas.*` 配置 |
|---|---|---|---|
| 重启 / 断电 | 保留 | 保留 | 保留 |
| 刷机（保留配置） | **只有刷含本机制的包才在**（rootfs） | 保留（`/etc/config` 在 keep 清单） | 保留 |
| 刷机（不保留配置） | 看包 | 丢失，需重建 | 丢失，用默认 IP |
| 恢复出厂 | 看包 | 丢失 | 丢失，用默认 IP |

> 关键：规则在 `/etc/config`（overlay，刷机保留），脚本在 rootfs（squashfs，随包走）。
> **两者必须配套**。刷了不含脚本的旧包，规则还在但地址不再自动跟随。

### 3.4 为什么 MAC 不写进仓库

仓库是公开的，MAC 属于设备标识。脚本改为按内网 IPv4 反查（IP 不敏感、恢复出厂后也好记）。
确实想钉死 MAC 时配 `ax6000.nas.mac`，脚本会跳过反查。

## 4. 一次前缀变化的完整时序

```
PPPoE 重拨
   │  ISP 下发新 PD
   ▼
netifd 更新 wan_6 / br-lan  →  发出 ifupdate 事件
   │
   ▼
/etc/hotplug.d/iface/90-nas-v6   （flock 抢锁）
   │
   ▼
/usr/sbin/nas-v6-firewall
   ├─ 读 br-lan 当前公网前缀 → norm6 归一化
   ├─ 现有 dest_ip 仍通过前缀+ping？ → 是：退出（无操作）
   ├─ 192.168.6.4 → ip neigh → MAC
   ├─ ip -6 neigh 按 MAC 取候选 → 前缀校验 + ping 校验
   ├─ 都不行 → 前缀 + EUI-64 兜底 → ping 校验
   └─ 写 dest_ip → uci commit → fw4 reload → logger 记一行
```

## 5. 演进逻辑与踩过的坑

这套东西不是一次写对的，每一版都是被实机数据打回来的。

### 5.1 版本演进

| 版本 | 做法 | 为什么改 |
|---|---|---|
| v0 | LuCI 里一条 `dest='*'` 的放行规则 | 最初能用，但内网所有设备都被开放 |
| v1 | 写死 NAS 的 IPv6 到 `dest_ip` | 收窄了范围，但前缀一换就失效 |
| v2 | 按 MAC 解析（IP→MAC→v6），hotplug 触发 | 解决漂移；但取"第一个匹配" |
| v3 | 加前缀校验 + ping 校验 + EUI-64 兜底 + 10 分钟定时器 | 解决旧前缀残留；但解析用 `cut -f1-4` |
| v4（当前） | `norm6` 归一化 + `flock` + 沿用当前值 + 归一化比较 | 修压缩地址错位、并发、无谓改写 |

### 5.2 具体漏洞清单

#### ① 原规则对内网全开放

- **现象**：`firewall.@rule[9]` 是 `dest='*'`，`nft` 里没有任何 `daddr` 约束。
- **后果**：内网每一台设备的 36353-36354 都对公网可达。
- **修复**：改为具名 section `nas_v6_ports`，由脚本维护 `dest_ip`。

#### ② 写死地址会被前缀漂移打死

- **根因**：PD 前缀是租约，重拨/续租/局端调整都会变。
- **修复**：改成运行时解析（§2.2）。

#### ③ 邻居表残留旧前缀地址（最隐蔽的一个）

- **发现方式**：实机 `ip -6 neigh show dev br-lan`，同一 MAC 有 4 条记录，
  其中 `240e:...:9b4d:c300:...` 是上一轮 PD 留下的。
- **后果**：取"第一个"一旦命中旧地址，规则被钉在死地址上；
  更糟的是写入"成功"之后不会再自纠——**静默错误**。
- **修复**：前缀校验 + 连通校验 + 沿用当前值（§2.3）。

#### ④ `cut -d: -f1-4` 对压缩地址错位

- **现象**：
  ```
  fd31:a5df:b924::1  ->  fd31:a5df:b924:     ← 末尾多一个空段
  2001:db8::1        ->  2001:db8::1         ← 整段没切对
  ```
- **根因**：`::` 在字段切分里表现为空字段，`-f1-4` 会切到空位。
- **后果**：公网前缀恰好没有 0 段（`240e:341:9b00:9e00`），所以一直"碰巧正确"；
  一旦 ISP 下发带 0 段的前缀，前缀校验全部失配 → 落兜底 → 拼出非法地址 → ping 失败 →
  规则卡在旧地址，日志只有一行"没有可用地址"。
- **修复**：`norm6()` 展开成 32 位十六进制再比。

#### ⑤ 无并发保护

- **根因**：hotplug 与 10 分钟定时器可能同时触发。
- **后果**：两次 `uci commit` + `fw4 reload` 竞争，日志重复、做无用功。
- **修复**：`flock -n`。

#### ⑥ 没有"沿用当前值"

- **根因**：每次都从头重新推导，而多前缀/邻居表排序会变化。
- **后果**：两个都合法的地址之间来回跳，每跳一次就是一次全量 `fw4 reload`。
- **修复**：现有值通过校验就直接退出。

#### ⑦ 零填充形式导致无谓改写

- **现象**：EUI-64 兜底拼出 `240e:0341:9b00:9e00:...`，与邻居表里的 `240e:341:...` 字符串不等。
- **修复**：比较用归一化值（同 ④ 的 `norm6`）。

#### ⑧ 自己引入的挂死 bug（awk 读 stdin）

- **现象**：加上 `norm6()` 后脚本直接卡住不返回。
- **根因**：`awk -v ip="$1" '{ ... }'` 没写 `BEGIN`，awk 会从 stdin 读输入，
  在 daemon 环境下永不结束。
- **教训**：这类问题看代码看不出来，**必须上机跑**。现已全部改为 `BEGIN` 包裹。

### 5.3 上机验证用例

| 用例 | 期望 | 实际 |
|---|---|---|
| 规则指向旧前缀 `240e:...:9b4d:c300:...` | 纠正到当前前缀 | ✅ |
| 清空 NAS 全部 v6 邻居条目 | EUI-64 兜底算出正确地址 | ✅ |
| 当前地址有效时重复执行 | 无日志、无写操作（幂等） | ✅ |
| 零填充写法与紧凑写法 | 判定为同一地址，不改写 | ✅ |
| 压缩地址前缀解析（6 种写法） | 同一 /64 判定一致 | ✅ |
| 两个实例同时执行 | 只有一个进入临界区 | ✅ |

## 6. 已知边界（当前不处理的）

| 问题 | 影响 | 为什么不处理 |
|---|---|---|
| 前缀变了但既无事件、定时器也未到 | 最多 10 分钟外网不可达 | 缩短轮询会带来无谓 reload；家庭场景可接受 |
| 局域网内伪造该 MAC | 规则可能被引到伪造主机 | 需要攻击者已在 LAN 内、且能仿冒 EUI-64 后缀 |
| EUI-64 兜底依赖设备真的用 EUI-64 | 兜底失效，但邻居表路径不受影响 | 兜底只是加速恢复，不是唯一手段 |
| 每次变化都是全量 `fw4 reload` | 毫秒级中断 | 改 nft 局部更新复杂度高一个量级，而变化很罕见 |
| `uci commit` 与 LuCI 并发 | 本轮静默失败 | 下一轮定时器会自愈 |

## 7. 运维手册

### 7.1 看状态

```sh
uci get firewall.nas_v6_ports.dest_ip     # 规则当前指向的地址
nft list ruleset | grep 36353             # 实际生效的 nft 规则
logread -e nas-v6-fw | tail -10           # 变更历史 / 失败原因
/etc/init.d/ax6000-nas-v6-watch status    # 兜底服务是否在跑
```

### 7.2 手动触发

```sh
/usr/sbin/nas-v6-firewall
```

### 7.3 日志对照表

| 日志内容 | 含义 | 处理 |
|---|---|---|
| `dest_ip X -> Y` | 正常变更 | 无需处理 |
| `无法从 192.168.6.4 解析 MAC（设备离线？）` | NAS 不在 ARP 表 | 检查 NAS 是否在线 / LAN 口 |
| `<MAC> 没有可用的全局 IPv6` | 前缀未生效或 SLAAC 未完成 | 等一轮；仍失败则查 `ip -6 addr show br-lan` |
| `br-lan 没有公网 IPv6 前缀` | WAN v6 没起来 | 查 `ubus call network.interface.wan_6 status` |
| `规则 nas_v6_ports 不存在，跳过` | 规则被删或改回匿名 section | 重建规则或改回具名 |

### 7.4 换 NAS

```sh
uci set ax6000.nas.ip='192.168.6.5'
uci commit ax6000
/usr/sbin/nas-v6-firewall
```

### 7.5 回滚

把 `dest_ip` 写死成当前地址即可（脚本会认为"仍然有效"而不再改动），
或者停掉兜底服务：

```sh
/etc/init.d/ax6000-nas-v6-watch stop
/etc/init.d/ax6000-nas-v6-watch disable
```

## 8. 关键代码

```sh
# 归一化：把任意写法的 IPv6 展开成 32 位十六进制
norm6() {
	awk -v ip="$1" '
		function pad4(g) { g = tolower(g); while (length(g) < 4) g = "0" g; return g }
		BEGIN {
			d = index(ip, "::")
			if (d > 0) { l = substr(ip, 1, d - 1); r = substr(ip, d + 2) }
			else       { l = ip; r = "" }
			nl = (l == "") ? 0 : split(l, a, ":")
			nr = (r == "") ? 0 : split(r, b, ":")
			if (nl + nr > 8) { print ""; exit }
			o = ""
			for (i = 1; i <= nl; i++) o = o pad4(a[i])
			for (i = 1; i <= 8 - nl - nr; i++) o = o "0000"
			for (i = 1; i <= nr; i++) o = o pad4(b[i])
			print o
		}'
}

# 候选地址是否可用：/64 属于当前前缀 + 真的 ping 得通
valid_addr() {
	k="$(pfx_key "$1")"
	[ -n "$k" ] || return 1
	echo "$PREFIX_KEYS" | grep -qx "$k" || return 1
	ping_ok "$1"
}
```

完整实现见 `files/usr/sbin/nas-v6-firewall`。
